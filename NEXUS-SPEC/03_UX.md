# NEXUS — 03 UX / INTERACTION SPECIFICATION

## Scope

This document specifies every user-facing interaction in NEXUS at implementation precision:
information architecture and screen inventory, the app shell, canvas interaction state tables with
exact pointer + modifier bindings, the full keyboard map with browser-conflict analysis, the paste
and drag&drop pipelines, command palette, inspector, context menus, the overlay system, all empty /
loading / partial / error / offline states with final English microcopy, onboarding, presentation
mode, mobile/tablet, and accessibility. Visual values (colors, type, spacing, easing curves) come
from `04_DESIGN_SYSTEM.md`; renderer mechanics from `05_CANVAS_ENGINE.md`; data shapes from
`08_DATA_MODEL.md`. Where this document and `00_MASTER.md` disagree, `00_MASTER.md` wins.

---

## 1. Interaction principles (binding rules)

1. **Direct manipulation first.** Anything visible on the canvas is manipulable in place; dialogs are
   for confirmation and review, never for primary object editing.
2. **Never modal without cause.** A modal is allowed only for destructive confirmation, proposal
   review, or a flow that must not be interrupted (auth, acceptable use). Everything else is a
   panel, sheet, popover or inline control.
3. **Every state has a designed rendering.** For each surface: `empty`, `loading`, `partial`,
   `error`, `offline`, `success`, `disabled`, `no-permission`. Missing states are gate failures
   (`00_MASTER.md` §8.2).
4. **Reversible by default.** Every mutation is undoable (N3). Confirmation dialogs exist only where
   undo is impossible (permanent delete, sign-out with unsynced local data, tool run that leaves the
   deployment).
5. **Feedback within 100 ms.** Every input produces a visible acknowledgement within 100 ms, even if
   the result takes 3 s (skeleton, spinner-in-place, optimistic node).
6. **Progressive disclosure.** Level 1 = canvas + card; level 2 = hover affordances; level 3 =
   inspector; level 4 = command palette / advanced panels. No feature is *only* reachable at level 4,
   and every feature is reachable *from* level 4.
7. **Pointer parity.** Every pointer action has a keyboard equivalent (N6).
8. **Quiet chrome.** Chrome does not animate on hover unless the animation communicates state.

## 2. UX behavior rules (roadmap §36, §39)

| Rule | Concrete requirement |
|---|---|
| Predictable | identical gesture ⇒ identical result in every mode; no context-dependent meaning of a bare click |
| Immediate | optimistic local mutation, then reconciliation; never block the canvas on network |
| Legible state | `Saved / Saving… / Offline / Reconnecting` always present in the status bar (N2) |
| Interruptible | every long operation (run, import, export, layout, replay) has a visible Cancel that leaves consistent state |
| Non-destructive automation | auto-layout, AI, imports are previewed, then applied as one undo entry |
| Loss-proof | in-progress text is committed to the Y.Doc on every 400 ms idle and on blur; navigating away never discards typing |
| Explainable | any automatic change exposes "Why?" listing rule/tool/model and inputs |
| No dead ends | every error state offers at least one action other than dismissal |

## 5. Camera and viewport

| Property | Value |
|---|---|
| Zoom range | 0.05 – 4.0, clamped |
| Zoom steps (keyboard/buttons) | ×1.2 per step, snapped to the nearest of 0.05,0.1,0.25,0.5,0.75,1,1.5,2,3,4 |
| Wheel zoom | `Ctrl`/`Cmd` + wheel, or trackpad pinch; anchored at pointer; 1 wheel notch = ×1.1 |
| Bare wheel | vertical pan (60 px per notch); `Shift`+wheel = horizontal pan |
| Pan gestures | `Space`+drag (any button), middle-drag, `H` hand mode + drag, two-finger trackpad, right-drag disabled (reserved for context menu) |
| Kinetic pan | trackpad only, friction 0.92/frame, stops below 0.4 px/frame |
| Edge auto-pan | while dragging within 48 px of a canvas edge: 12 px/frame max, ramped linearly from 0 |
| Zoom to fit | `Ctrl+1` — fits all content with 64 px padding, max zoom 1.0 |
| Zoom to selection | `Ctrl+2` — fits selection with 96 px padding, max zoom 1.5 |
| Reset zoom | `Ctrl+0` — zoom 1.0, keeps viewport center |
| Camera restore | board open restores last camera per user; `?c=` overrides |
| LOD switch | `zoom < 0.55` renders canvas LOD glyphs (`05_CANVAS_ENGINE.md` §4); crossing the threshold cross-fades over 120 ms |
| Motion | all camera tweens 220 ms `--ease-out-quint`; `prefers-reduced-motion` ⇒ instant jump |

Minimap: 200×140 px, bottom-right, 12 px inset, toggle `M`. Shows LOD dots, groups as filled rects,
viewport as a 1 px accent rect. Click = center; drag rect = pan; wheel over minimap = zoom;
`Shift`+drag on empty minimap area = marquee-zoom to that region. Auto-hides after 4 s idle at
opacity 0.35, returns to 1.0 on pointer within 120 px.

## 6. Canvas interaction specification

### 6.1 Mode model

The canvas is a finite state machine (`05_CANVAS_ENGINE.md` §6). Modes: `idle`, `panning`,
`marqueeSelect`, `dragNodes`, `resizeNode`, `connectEdge`, `editText`, `handTool`,
`presentation`, `readOnly`. Rules: only one mode active; every mode has an `Escape` exit that
restores pre-mode state; a mode never survives a pointer-up except `editText`, `handTool`,
`presentation`, `readOnly`.

Deliberate exclusions, with justification (roadmap §4 asked for a graphical workspace, not a vector
editor): **no rotation** (typed cards are text-bearing; rotation harms legibility and complicates
hit-testing and edge anchoring for zero analytic value) and **no lasso select** (marquee plus
`Shift`-click plus focus-mode neighborhood selection cover every real case at a fraction of the
hit-testing cost). Both are recorded here so no phase re-opens the question.

### 6.4 State table — marquee select

| Phase | Behavior |
|---|---|
| start | left press on empty canvas; marquee begins after 3 px of movement (below that it is a click) |
| during | 1 px accent border, `--accent-subtle` 12% fill; candidate nodes get a 1 px dashed accent outline; live count chip at the cursor ("18 nodes") |
| intersection rule | default = intersect (any overlap selects); `Alt` held = contain (fully inside only) |
| modifiers | `Shift` = add to existing selection; `Alt+Shift` = subtract; bare = replace |
| edges | edges are selected only when both endpoints are selected, or when the marquee crosses the edge and `E` is held |
| auto-pan | active near viewport edges (§5) |
| commit | on pointer-up; empty marquee (< 3 px) clears selection |
| cancel | `Escape` during drag restores the prior selection exactly |
| perf | candidate query via spatial index each frame, capped at 16 ms; above 20,000 candidates the outline pass is skipped and only the count updates |

### 6.5 State table — drag nodes

| Phase | Behavior |
|---|---|
| threshold | 3 px (pointer) / 8 px (touch) |
| payload | full selection; locked nodes excluded and reported once in a toast: "3 locked nodes weren't moved." |
| snapping | node edges/centers within 6 screen px, equal-spacing detection across 3+ nodes, group bounds, grid when grid-snap is on (`Ctrl+'`); `Ctrl` held suppresses all snapping |
| guides | 1 px accent lines, dimension labels for equal spacing; max 6 guides rendered |
| edges | attached edges re-route live at 60 fps using the cheap router; the smart router re-runs in the worker on drop (`07_EDGE_SYSTEM.md` §5) |
| groups | hovering a group ≥ 300 ms with the pointer inside its bounds highlights it and re-parents on drop; `Ctrl` prevents re-parenting |
| z-order | dragged nodes render above all others for the duration |
| commit | one Y.Doc transaction on pointer-up ⇒ one undo entry |
| cancel | `Escape` mid-drag returns nodes to origin and cancels the transaction |
| perf | positions written to a transient layer during drag; the Y.Doc receives the final position only (plus 200 ms-throttled awareness for collaborators) |

### 6.6 State table — connect edge

| Phase | Behavior |
|---|---|
| entry | drag from a connect ring; or select a node and press `C`; or `>` grammar in quick-add |
| rubber band | 2 px accent bezier from the source anchor to the cursor, arrowhead at cursor |
| type preselect | default relation from a type-pair matrix (`07_EDGE_SYSTEM.md` §3), shown as a chip on the band; `Tab` cycles legal types; `1..9` picks directly |
| targets | valid targets get an accent border; nearest anchor snaps within 24 px |
| drop on empty | opens quick-add prefilled with the pending relation; creating a node completes the edge; `Escape` cancels both |
| drop on invalid | rubber band turns `--danger`, tooltip states the reason; release cancels with no side effect |
| multi-source | with N nodes selected, dragging a ring creates N edges to the target in one undo entry |
| commit | one transaction: edge(s) + optional new node |
| keyboard | `C` then `Tab`/arrows to traverse candidates, `Enter` to connect, `Escape` to abort |

### 6.7 State table — resize / text edit

Resize: 8 handles (4 corners 10×10 px, 4 sides 6 px), min 120×64 px, max 4,000×4,000 px world units.
`Shift` = aspect lock, `Alt` = from center, `Ctrl` = ignore snapping. Image nodes keep aspect by
default (`Shift` frees it). Text nodes auto-grow vertically; a manual vertical resize pins the height
and shows a "Fit height" quick action.

Text edit: enter with double-click, `Enter` on a selected text node, or `T` for a new node. Caret at
the click position. Toolbar appears on selection of ≥ 1 character (bold, italic, code, link, H1–H3,
list, quote, highlight). `Escape` exits to node-selected, `Ctrl+Enter` exits and creates a sibling
node below at 24 px gap. Content commits on 400 ms idle and on blur. `Tab` inside a list indents;
outside a list it exits edit mode and moves focus (so `Tab` never inserts a tab character).

### 6.8 Groups

Create: select ≥ 2 nodes, `Ctrl+G`. Header 28 px with name, count, collapse chevron, color dot.
Collapse (`Ctrl+Shift+G`) shrinks to a 240×72 px card; edges to interior nodes re-anchor to the
collapsed card and fan-label with counts ("5 relations"). Dropping a node on a collapsed group adds
it. Ungroup `Ctrl+Shift+U` keeps positions. Nesting depth limit 3 (guard: deeper nesting makes
routing and hit-testing costs superlinear for no observed benefit).

## 7. Paste pipeline

`Ctrl+V` / `Cmd+V` is the front door (`00_MASTER.md` §3.2). One entry point, deterministic routing.

### 7.1 Placement rules

Resolution order for where pasted content lands:
1. If a node is in `editText` mode → paste into the text (native behavior, sanitized HTML).
2. Else if the last pointer position is over the canvas → paste at that world point.
3. Else → paste at viewport center, offset by a spiral placement to avoid overlap (24 px pitch).
4. If the incoming count > 12 items → route to the inbox lane instead, with a toast
   "18 items added to Inbox. Open Inbox" (`01_PRODUCT.md` §6.14).
Multiple items are laid out in a grid of `ceil(sqrt(n))` columns, 280×180 px cells, 24 px gutters,
and are selected as a set after creation so the user can immediately move or group them.

### 7.2 Detection order

Clipboard is inspected in this priority order (first match wins per item, all items processed):

```text
1. files[] present (DataTransfer.files)              → per-file branch (§7.3.8)
2. image/* blob in items (no filename)               → screenshot branch (§7.3.3)
3. text/html present AND contains >1 anchor          → html branch (§7.3.5)
4. text/plain is a single valid absolute http(s) URL → url branch (§7.3.1)
5. text/plain is 2..200 lines, ≥60% valid URLs      → multi-url branch (§7.3.2)
6. text/html present (formatted, ≤1 anchor)          → rich text branch (§7.3.6)
7. text/plain matches code heuristic (§7.3.9)        → code branch
8. text/plain, internal NEXUS payload marker         → node/subgraph paste (§7.9)
9. text/plain otherwise                              → text branch (§7.3.7)
10. nothing usable                                    → error toast (§7.6)
```

URL validation: `new URL()` parses, scheme in `{http, https}`, host is not a private range literal,
length ≤ 2,048. Non-http schemes (`mailto:`, `ftp:`, `magnet:`) become text nodes with a chip
offering "Create email entity" for `mailto:`.

### 7.3 Per-shape behavior

**7.3.1 Single URL.** Create a `website` node immediately in `loading` state showing favicon
placeholder + the URL's host + path. Fire unfurl (`09_BACKEND.md` §5). On success patch title,
description, preview image, canonical URL, favicon, `published_at`; flash success (§6.3). On failure
keep the node, set `partial`, body copy: "Couldn't load a preview. The page may be blocked or
offline." with actions Retry / Open in browser / Convert to note. Special-cased hosts produce
richer types via manifest hint: a GitHub repo URL creates a `repository` node (P10); a recognized
social profile URL creates an `account` node with `platform` and `handle` extracted (P11 mapping
table). Detection is data-driven from `packages/integrations` URL patterns, never hardcoded in the
canvas.

**7.3.2 Multiple URLs.** Create one node per URL, deduplicated against the board (§7.7) and against
each other. If count ≤ 12 → grid on canvas; else → inbox. Unfurls run with a concurrency of 4 and a
progress chip at the bottom-center: "Loading previews 7/18 · Cancel". Cancel stops pending unfurls
and leaves nodes in `partial`. A follow-up chip offers "Connect all to…" which enters a connect
gesture with the whole set as source.

**7.3.3 Screenshot / image blob.** Create an `image` node at natural size, downscaled to fit a
600 px max dimension in world units, with an OPFS-backed local blob so it renders before upload.
Upload runs in the background: node shows a 2 px progress bar along its bottom edge. On upload
failure: "Couldn't upload this image. It's still saved on this device." + Retry. EXIF is read for
`captured_at` and GPS (offered as "Add location?" chip, never applied silently); EXIF is stripped
from the stored derivative but the original is kept in the raw blob for chain-of-custody
(`01_PRODUCT.md` §6.10).

**7.3.4 Image with a source URL** (copied from a web page: html + image). Node stores both
`file_ref` and `source_url`; the inspector shows "From example.com/page" as a link, and a
`derived_from` edge is created if that page already exists as a node on the board.

**7.3.5 HTML with multiple links.** Show the disambiguation chip (§7.4) with options:
`Create 14 link nodes` (default) · `Keep as one rich text note` · `Extract entities…` (P13: AI
extraction proposal). Default is applied optimistically after 4 s if the user does nothing; the chip
then converts to an undo affordance ("14 link nodes created · Undo").

**7.3.6 Rich text.** Create a `text` node preserving headings, bold/italic/code, lists, blockquotes
and links. Sanitize with an allowlist (`15_SECURITY.md` §6): drop `script`, `style`, `iframe`,
event attributes, `on*`, and any inline styles except text alignment. Images inside the HTML become
a chip "3 images not imported · Import them" (explicit, because remote image fetching is an egress
event).

**7.3.7 Plain text.** ≤ 280 characters → `note` node sized to content. > 280 → `text` node
420×min(content, 520) px. If the text contains recognizable indicators (emails, IPs, domains,
`@handles`, hashes), a chip offers "Found 6 indicators · Create entities" which opens an extraction
proposal listing each candidate with a checkbox and inferred type — never auto-created.

**7.3.8 Files.** Per file: sniff type server-side (never trust MIME). Images → `image` node; PDF →
`file` node with first-page thumbnail and page count; CSV/JSON → `file` node with a 20-row/10-key
preview and a "Create nodes from rows…" action (mapping sheet, P15); DOCX/XLSX → `file` node with
extracted text preview; ZIP → `file` node with a listing of up to 50 entries, no auto-extraction
(archive bombs). Size limits: 100 MB per file, 500 MB per paste batch; over limit ⇒
"That file is 240 MB. The limit is 100 MB per file." + "Link it instead" action (stores a reference).

**7.3.9 Code.** Heuristic: ≥ 2 lines and (leading indentation on ≥ 40% of lines, or ≥ 3 of
`{};()=>`, `def `, `function `, `class `, `import `, `#include`). Creates a `text` node with a code
block, language guessed from a token map, monospace, no wrap, horizontal scroll, copy button. A chip
offers "Not code · Convert to text".

**7.3.10 Folder** (drag&drop only, `webkitGetAsEntry`). Traverse to depth 4, cap 200 files,
30 MB average guard. Creates a `group` named after the folder, containing one node per file, laid out
in a grid, with a summary chip "Imported 47 of 62 files · See skipped" listing skipped items with
reasons (too large, unsupported type, depth limit).

**7.3.11 Mixed clipboard** (e.g. text + image + 2 files). Process every item by its own branch;
group results only if `n > 3`, into a group named "Pasted 14:32". One toast summarizes:
"Added 5 items: 2 images, 1 link, 2 files." with Undo.

### 7.4 Disambiguation affordance

A single reusable control, the **paste chip**: a 320 px popover anchored 12 px below the created
content, with 1 primary and up to 3 secondary options, a 4 s progress hairline showing the default
being applied, and `Tab`/arrow key navigation. Rules: it never blocks input; it never appears for
unambiguous shapes; it converts into an Undo chip after the default applies; `Escape` accepts the
default; pressing `1..4` picks an option directly. It appears for shapes 7.3.5 (html multi-link),
7.3.7 (indicators found), 7.3.9 (code), 7.3.10 (folder partial import) and for any input where two
type mappings scored within 0.15 of each other in the detector.

### 7.5 Paste performance contract

Node visible ≤ 400 ms p95 (S3 in `01_PRODUCT.md` §7.3) regardless of clipboard size; detection runs
synchronously on ≤ 64 KB of text and is offloaded to a worker beyond that; blobs never pass through
the main thread more than once (transferred, not copied).

### 7.6 Paste failure states

| Case | Copy |
|---|---|
| Clipboard permission denied (browser API path) | "NEXUS can't read the clipboard. Press Ctrl+V with the canvas focused, or allow clipboard access in your browser settings." |
| Empty clipboard | "Nothing to paste." (toast, 2 s, no action) |
| Unsupported only (e.g. a proprietary flavor) | "That clipboard content isn't supported. Copied text or an image will work." |
| Over batch limit | "That's 340 items. NEXUS pastes up to 200 at once — the first 200 were added." |
| Offline + URL | node created, chip "Preview will load when you're back online." |

### 7.7 Paste-time deduplication

Every created node's normalized key is checked against the board index
(`01_PRODUCT.md` §6.3). On hit: the existing node is flashed and centered instead of creating a
duplicate, with a toast "Already on this board · Add anyway". "Add anyway" creates the node and marks
the pair as not-duplicates.

### 7.8 Copy / cut

`Ctrl+C` on a selection writes three flavors: (a) `text/plain` — human-readable list (titles + URLs,
one per line); (b) `text/html` — a list with anchors; (c) `text/plain` with a fenced
`nexus:clipboard:v1` JSON payload containing nodes, edges, group structure, tag references and blob
references. `Ctrl+X` copies then deletes as one undo entry. Copying an image node also writes the
image bitmap when it is ≤ 8 MB, so the OS can paste it elsewhere.

### 7.9 Pasting NEXUS payloads

Same board: nodes are duplicated with new ids at +24/+24 px offset, edges between copied nodes are
preserved, edges to non-copied nodes are dropped (with a chip "4 connections weren't copied · Copy
those too"). Other board / project: blobs are re-referenced (copy-on-write in storage, not
re-uploaded); missing tags are created; provenance is preserved and a `derived_from` edge back to the
origin node is created *only across boards* (so cross-board lineage stays traceable). Payload from a
newer schema version: "This content came from a newer version of NEXUS. Some fields were skipped."

## 9. Command palette and search

### 9.1 Invocation and shape

`Ctrl+K` / `Cmd+K` anywhere. Centered overlay, 640 px wide, top offset 15vh, max height 60vh,
backdrop blur 8 px at 40% black. Open → first paint ≤ 80 ms (S6): the palette renders from a
prebuilt index in memory, never awaiting the network. `Escape` closes and returns focus exactly.

### 9.2 Modes

Mode is chosen by a leading token; the current mode shows as a removable chip (`Backspace` at
position 0 removes it and returns to `all`).

| Token | Mode | Searches |
|---|---|---|
| *(none)* | all | actions + nodes + boards + collections + runs, interleaved by score |
| `>` | commands | every registered action |
| `@` | nodes | nodes on the current board |
| `@@` | nodes (project) | nodes across the project |
| `#` | tags | tags, then nodes bearing them |
| `/` | boards | boards + projects |
| `~` | runs | integration runs, by tool/target/status |
| `?` | help | shortcut lookup, docs entries, "What can I do here?" |
| `:` | goto | `:x,y,z` camera coordinates, `:node <id>`, `:v graph` view switch |
| `=` | AI ask | natural-language request → produces a Proposal, never a direct mutation (N4) |

### 9.3 Scoring

```text
score = 0.45 * fuzzyMatch(query, label)        // Smith-Waterman-ish, prefix and word-boundary boosts
      + 0.20 * recencyBoost(lastUsedAt)        // exp decay, half-life 7 days
      + 0.15 * frequencyBoost(useCount)        // log1p(count) / log1p(maxCount)
      + 0.10 * contextRelevance(selection)     // action applies to the current selection/type
      + 0.10 * pinnedOrExactMatchBonus
minimum display score: 0.18 ; ties break by shorter label, then alphabetical
```

Empty query shows: **Recents** (last 5 actions), **Suggested for selection** (up to 4 context
actions), **Jump to** (3 most recent boards). Results are grouped with sticky group headers, max 8
per group, virtualized list above 50 rows.

### 9.4 Action taxonomy

Registered in `packages/domain/actions` with `{ id, label, group, keywords, shortcut, when, run,
undoable, dangerous }`. Groups: **Create** (node types, board, project, group, hypothesis),
**Edit** (rename, retype, tag, confidence, color, merge, split, lock, hide, delete),
**Select** (all, none, invert, by type, by tag, neighbors, orphans, unsourced),
**Arrange** (align 6, distribute 2, layout 5, group/ungroup, z-order 4),
**View** (view modes, zoom, focus, minimap, grid, snap, theme contrast),
**Capture** (quick add, from clipboard, from URL, open inbox),
**Enrich** (run integration per manifest, re-run, watch, unwatch),
**Analyze** (find path, shortest path, cluster, dedupe scan, health panel, ACH view),
**AI** (summarize, explain, suggest links, extract entities, draft report section),
**Share** (share link, redaction profile, export JSON/MD/PDF/archive, present),
**Navigate** (goto board/node/run, back/forward, recent),
**System** (settings, shortcuts, keyboard help, sync details, report an issue, sign out).

Rules: `when(ctx)` hides inapplicable actions rather than disabling them, except for the 12 core
actions that must always be visible to remain discoverable (those show disabled with a reason
tooltip). Dangerous actions require `Enter` twice with the second press labelled "Press Enter again
to delete 24 nodes".

### 9.5 Search surface (non-palette)

Top-bar field and `/` open the same index with a results dropdown (max 8) plus "See all results"
→ `/search`. Filters as chips: type, tag, confidence range, date range, source tool, has-comment,
board, project. Result rows show type glyph, title, 120-char snippet with matched terms in
`--accent`, board name, and `observed_at`. `Enter` = go to node (pan + select + flash);
`Ctrl+Enter` = open in a split view; `Alt+Enter` = add to current board as a reference.
Saving a query (`Ctrl+S` in the search surface) creates a smart collection with the current filters.

## 10. Inspector specification

### 10.1 Common structure

Header (title, type chip, confidence control, pin/lock/watch toggles, `⋯` menu), then tabs.
All fields commit on blur or 400 ms idle; every field has an inline validation state and an
"unsaved" dot that clears when the mutation is durable locally. Fields the user cannot edit
(tool-provided facts) are shown read-only with a "from GitHub · 12 Aug 09:14" caption and an
"Override" action that creates a user-set value while retaining the original in provenance.

Tabs: **Details** (type-specific), **Provenance** (source, tool, run, chain — `01_PRODUCT.md` §6.2),
**Connections** (grouped by relation type, with count, confidence and a hover-to-highlight; add and
delete inline), **History** (field-level diffs, §6.8 of `01_PRODUCT.md`), **Comments** (threads,
mentions, resolve).

### 10.2 `website` / `link`

Fields: title (text), URL (text, validated, "Open ↗"), canonical URL (read-only), domain
(read-only, link to a domain node — offers to create it), description (textarea, 3 rows),
preview image (thumb with Replace / Remove / Re-fetch), favicon, `published_at`, `captured_at`
(read-only), HTTP status of last fetch, content hash, archive snapshot link if one exists, tags,
confidence, notes. Actions: Re-fetch metadata, Save page snapshot, Extract entities, Run GitHub
analysis (when the URL is a repo), Open in browser, Copy URL.

### 10.3 `text` / `note` / `evidence`

Fields: body (rich text editor with the §6.7 toolbar), format toggle (rich/markdown source),
word count, `evidence` adds: source reference (node picker), quoted-from (page/line/timestamp),
collection method (`observed | received | derived`), confidence, chain-of-custody note.
Actions: Summarize (AI proposal), Extract entities, Convert to hypothesis, Copy as Markdown.

### 10.4 `image`

Fields: alt text (required for export; empty shows a warning chip "No alt text — add one for
accessible reports"), caption, dimensions (read-only), file size, format, hash, EXIF table
(collapsed), GPS (with "Create location node" action), crop (opens an inline cropper with aspect
presets and reset), rotation in 90° steps (image-only, not a canvas rotation), redaction brush
(draws opaque rects stored as a non-destructive overlay), source URL, tags, confidence.
Actions: Open fullscreen, Download original, Replace, Copy image.

### 10.5 `file`

Fields: filename (editable label; original name retained), type, size, hash, pages/rows/entries,
extracted text (collapsed, searchable), preview (first page / first rows / archive listing),
uploaded-by, uploaded-at, virus-scan status if configured. Actions: Download, Preview fullscreen,
Re-extract text, Create nodes from rows (CSV/JSON), Summarize (AI).

### 10.6 `person` / `username` / `account` / `email`

`person`: display name, aliases (chips), notes, related accounts (auto from `same_as` edges),
locations, employers, confidence, sensitivity flag (`sensitive` tag drives redaction defaults).
`username`: handle, normalized handle, platforms checked (a table of platform · status
`found/not found/error/rate-limited` · URL · checked-at · run link), `same_as` candidates.
`account`: platform, handle, profile URL, display name, avatar, bio, followers/following counts,
created-at, verified flag, last-checked, and per-field provenance (Sherlock vs manual vs GitHub).
`email`: address, validity (syntax/MX/never-verified), provider, appears-in (nodes referencing it).
Actions across these: Run Sherlock, Run SpiderFoot (semi-active confirmation, §12.8 of
`01_PRODUCT.md` §10.2), Merge with…, Split…, Watch changes.

### 10.7 `domain` / `ip`

`domain`: name, registrar, created/updated/expires, name servers, WHOIS excerpt (read-only, with the
run link), resolved IPs (as `resolves_to` edges), subdomains found, TLS issuer/expiry.
`ip`: address, version, ASN, org, country, reverse DNS, open-port findings (only if a run produced
them), first/last seen. Both: confidence, tags, watch toggle, "Run SpiderFoot module…".

### 10.8 `repository`

Fields: full name, owner (link to `person`/`org` node), description, stars, forks, watchers, open
issues, primary language + language breakdown bar, license, topics, default branch, created/pushed
at, latest release (tag, date, notes excerpt), contributors (top 10 with commit counts), README
(rendered, collapsible, links clickable), install/usage snippet if detected, dependency count,
analysis summary from the repo agent (`11_GITHUB.md` §6) with a maintenance signal
(`active | slowing | dormant`) and the evidence behind it. Actions: Re-analyze, Open on GitHub,
Add as integration candidate, Compare with… (table view), Watch releases.

### 10.9 `hypothesis` / `query` / `tool_run`

`hypothesis`: statement (textarea), status (`open/supported/refuted/inconclusive`, human-set only),
support tally (Σ confidence of `supports` vs `contradicts`, rendered as a two-sided bar), evidence
list with per-item polarity toggles, "Open in ACH view".
`query`: the saved query definition, live count, run-now, "Select matches on board".
`tool_run`: tool, version/digest, target, parameters, started/finished, duration, exit status,
stdout/stderr excerpt (last 200 lines, monospace, copyable), produced entities (with import status),
raw payload download, "Re-run with same parameters", "Diff against previous run".

### 10.10 Edge inspector

Type (select, with the legal set per endpoint pair), direction (swap button), label, confidence,
basis, notes, provenance, created-by/at, routing override (`auto | straight | curved | orthogonal`),
"Highlight on canvas", Delete.

### 10.11 Multi-selection (bulk panel)

Header "N nodes selected · M edges". Sections: Tags (add/remove chips, indeterminate state for
partial), Confidence (set all), Color, Type (only within a compatible family; blocked with an
explanation otherwise), Connect all to… , Group, Lock, Hide, Export selection, Run integration on
all (shows an estimated cost/time and an item count), Delete. Each action = one undo entry with a
summary toast.

## 12. Feedback, states and error system

### 12.1 Copy pattern

Every message: **what happened** (past tense, plain), **why** (cause in user terms, no stack, no
codes in the body), **what to do** (an action, not advice). Max 140 characters for the body plus 1–2
action buttons. Technical detail (correlation id, HTTP status, tool exit code) lives behind
"Details". No exclamation marks, no "Oops", no blame ("you entered an invalid…" → "That URL isn't
valid").

### 12.2 Severity → surface

| Severity | Surface | Duration |
|---|---|---|
| Success confirmation | toast bottom-center | 3 s |
| Reversible success | toast with Undo | 8 s |
| Non-blocking failure of a background job | inline badge on the affected object + notification bell entry | until resolved |
| Failure of a user-initiated action | toast with Retry | 8 s, sticky if it repeats twice |
| Blocking failure (cannot continue) | inline panel in place of the surface | until resolved |
| Destructive confirmation | modal | until answered |
| Fatal (app broken) | full-screen error with correlation id and Reload | until reload |

Toast stack: max 3 visible, newest at the bottom, identical messages collapse with a count badge
("×4"), hovering pauses dismissal, `Escape` dismisses the top toast, `Ctrl+Shift+Z` triggers the
Undo of the newest undoable toast.

### 12.3 Canvas states

| State | Rendering + copy |
|---|---|
| empty board (new) | onboarding canvas (§20), not a blank void |
| empty board (all deleted) | centered plate: **"This board is empty."** / "Everything here was deleted or moved." / [Paste something] [Add a node] [Undo delete] |
| loading board | grid + skeleton cards at last-known positions (from the local snapshot), status bar `Loading…`; interactive within 2.5 s (S1) |
| partial (blobs missing) | affected image/file nodes show a placeholder glyph + "Preview unavailable offline" |
| error (document failed) | inline panel: **"Couldn't open this board."** / "The board data didn't load. Your local copy is intact." / [Retry] [Open last saved copy] [Details] |
| offline | status bar `Offline`; a one-time 6 s toast: **"You're offline."** / "You can keep working — changes are saved on this device." / [Details] |
| read-only (permission) | 2 px muted top border, chip "Read-only · Request access" |
| read-only (replay/checkpoint) | amber top border, chip "Viewing 12 Aug 14:20 · Exit" |
| filtered to nothing | plate: **"No nodes match these filters."** / "3 filters are active." / [Clear filters] |
| too-large board guard | at > 20,000 nodes, banner: **"This board is very large."** / "Performance may drop above 20,000 nodes." / [Split board…] [Dismiss] |

### 12.4 Panel states (inspector, inbox, runs, health)

Empty: inspector with nothing selected → board properties (never a blank panel). Inbox empty →
**"Inbox is clear."** / "Captures that aren't placed on the canvas land here." / [How capture works].
Runs empty → **"No runs yet."** / "Run a tool on a node to enrich it." / [Browse tools].
Health empty → **"Nothing to fix."** / "No orphans, unsourced nodes or duplicates found."
Loading: 3 skeleton rows, never a centered spinner. Error: inline card with Retry, panel chrome
intact. No-permission: **"You don't have access to this."** / "Ask a project admin for the Analyst
role." / [Request access].

### 12.5 Integration run states

| State | Copy / rendering |
|---|---|
| queued | "Queued · position 2" + Cancel |
| starting | "Starting the sandbox…" indeterminate bar |
| running | "Running · 00:42 · 128 of 400 sites checked" determinate when progress is parseable, else elapsed time |
| partial | "Finished with 3 errors. 218 results imported-ready." + [Review] [See errors] |
| rate-limited | **"The tool is being rate-limited."** / "GitHub allows 60 requests/hour without a token." / [Add a token] [Continue anyway] |
| timeout | **"The run hit the 10-minute limit."** / "Partial results were kept." / [Review partial] [Re-run with fewer modules] |
| failed | **"The run failed."** / "The tool exited with code 2 before producing results." / [See output] [Re-run] |
| cancelled | "Run cancelled. Nothing was imported." |
| tool unavailable | **"SpiderFoot isn't reachable."** / "The configured endpoint didn't respond." / [Check settings] [Use a different tool] |
| quota exceeded | **"You've used this month's run quota."** / "412 of 400 runs used." / [See usage] |
| authorization needed | modal: **"Confirm you're authorized."** / "This tool contacts the target directly. Confirm you have permission to test example.com." / [Cancel] [I'm authorized — run] |

### 12.6 Proposal review (imports and AI)

Modal 720 px: header "Import 218 results from Sherlock · run #f13c". Body = three tabs:
**Add (194)**, **Merge into existing (21)**, **Conflicts (3)**. Each row: type glyph, label,
confidence, source detail, checkbox; conflicts show field-level old → new with a radio per field.
Footer: "194 nodes, 210 edges will be added" · [Cancel] [Import selected]. Post-import toast:
"Imported 194 nodes · Undo". Empty proposal: **"Nothing new to import."** / "All 218 results already
exist on this board." AI proposals additionally show a rationale block and the cited node ids, plus
the cost actually spent.

### 12.7 Sync and conflict states

CRDT merges automatically, so "conflict" means *semantic* divergence worth surfacing, not a merge
failure. Cases:

| Case | Behavior |
|---|---|
| Concurrent field edit | last write wins per field; the losing author sees a 6 s toast "Your change to *Title* was replaced by Devon's edit" + [Restore mine] (writes the old value back) |
| Concurrent delete + edit | the delete wins; the editor sees "Devon deleted this node while you were editing" + [Restore node] which recreates it with the edited content |
| Server rejects an update (ACL changed mid-session) | "Your access to this board changed." / "Recent changes couldn't be saved to the server. They're still on this device." / [Export my changes] [Reload] |
| Version skew (client older than server schema) | blocking banner: "NEXUS was updated." / "Reload to keep editing safely." / [Reload now] — writes are disabled after 60 s |
| Long offline period, > 500 queued updates | on reconnect show a progress modal "Syncing 512 changes… 340/512" with Cancel that keeps everything local |

### 12.8 Destructive confirmations

Required only when undo cannot help: permanent delete from Trash, delete run + raw payload, delete
board/project, sign out with unsynced local changes, revoke a share link, apply a redaction profile
to an export (a review step, not a confirm). Pattern: modal, title states the object and count, body
states the irreversible consequence, primary button is the verb ("Delete 3 boards"), destructive
styling, `Enter` does *not* activate it (focus starts on Cancel); typing the object name is required
only for project deletion.

### 12.9 Fatal errors

Full-screen: **"NEXUS hit an unexpected error."** / "Your work is saved on this device." /
[Reload] [Copy diagnostics] and a small correlation id. The error boundary attempts a Y.Doc flush to
IndexedDB before rendering. Route `/oops/:code` is used for hard navigation failures.

## 19. Accessibility

Target: WCAG 2.2 AA plus the N6 requirements. Contrast ≥ 4.5:1 text / 3:1 UI, verified in
`04_DESIGN_SYSTEM.md` §3 token tests.

### 19.1 Landmark and focus structure

DOM order: skip links (`Skip to canvas`, `Skip to inspector`) → `banner` (top bar) →
`navigation` (project rail) → `main` (canvas application region) → `complementary` (inspector) →
`contentinfo` (status bar) → overlay portals. Tab order follows this order; panels are single tab
stops that delegate to internal roving focus.

### 19.2 Canvas as an accessible object

The canvas host is `role="application"` with `aria-roledescription="Research canvas"` and a
`aria-describedby` pointing at a hidden usage summary. It contains a **live DOM mirror** of the
visible node set: one focusable element per rendered node with `role="group"`,
`aria-label` composed as `"{type}: {title}. {n} connections. Confidence {label}. {state list}"`,
positioned absolutely to match the node so screen magnifiers track correctly. Off-screen nodes are
not in the mirror; the mirror is capped at 300 elements and, when the visible set exceeds that, the
canvas exposes a "Browse nodes as a list" affordance (`List` view) which is fully accessible by
construction. This cap is a deliberate trade: an unbounded mirror at 5,000 nodes would violate N1.

### 19.3 Roving tabindex and traversal

One node holds `tabindex="0"`; all others `-1`. `Tab` enters the canvas at the last-focused node
(or the top-left-most node in reading order: sort by `round(y/120)` then `x`). Inside the canvas:
`Tab`/`Shift+Tab` move through traversal order; `Alt+Arrow` moves to the nearest node in a direction
(cone of ±45°, nearest centroid); `Ctrl+Down` enters a group; `Ctrl+Up` exits to the group;
`Enter` edits; `Space` toggles selection; `C` then `Tab` cycles connect candidates with each
announced as `"Connect to {title}. Press Enter."`. Focus always scrolls the camera to keep the
focused node fully in view with 64 px padding, using an instant jump under reduced motion.

### 19.4 Screen-reader model of the graph

Three complementary presentations, all from the same data:
1. **Node announcement** (above) for spatial navigation.
2. **Connections list** in the inspector: a real `<ul>` grouped by relation type, each item a link
   that moves focus to the neighbor and announces `"{relation} {direction} {title}"`.
3. **Outline view** (`Ctrl+Alt+O`): a `role="tree"` of groups → nodes → connections, keyboard
   navigable, which is the recommended way to read a large board non-visually and is what the
   mobile Board tab reuses (§18.2).
Live regions: `aria-live="polite"` for sync state, selection count, run progress and toast text;
`aria-live="assertive"` only for destructive-confirmation results and fatal errors. Announcements are
debounced to at most one per 500 ms and coalesced ("3 nodes added").

### 19.5 Visual and motor accessibility

Focus ring: 2 px `--focus-ring` + 1 px dark outer contour so it is visible on every surface; never
removed, never replaced by color alone. All state is dual-encoded (never color-only): confidence uses
opacity + a text chip, edge confidence uses dash pattern + inspector value, errors use icon + text,
presence uses color + name label. Hit targets ≥ 24×24 px on pointer, ≥ 44×44 px on touch. No
drag-only operation: every drag has a menu/keyboard path (move via arrows, connect via `C`, resize
via inspector width/height fields, reorder via `Ctrl+Shift+Arrow`). Text zoom to 200% must not clip
chrome (panels become overlays below 1024 effective px). Autoplay: none. Timeouts: none that lose
work; the 4 s paste-chip default is undoable for 8 s afterwards.

### 19.6 Reduced motion, high contrast, and AT modes

`prefers-reduced-motion: reduce` → §13 rules. `prefers-contrast: more` → borders go to
`--border-strong`, dim states go from 12% to 35% opacity, decorative shadows drop.
`forced-colors: active` → all custom surfaces map to system colors, canvas LOD glyphs are drawn with
`CanvasText`, and the edge dash patterns carry the confidence meaning (since opacity is unavailable).
Settings → Accessibility offers: "Screen reader optimizations" (disables single-letter creation keys,
enlarges the DOM mirror cap to 600, promotes the outline view), "Always show focus", "Reduce
transparency", "Increase hit targets", "Disable canvas animations".

### 19.7 Testing hooks

axe-core runs in CI on every route and on the canvas with 50 nodes; a Playwright keyboard-only suite
completes the full core loop (capture → connect → run → import → export) without any pointer event;
a screen-reader snapshot test asserts the announcement strings for each node type. Failures block
the phase gate (N6).

## 21. Open risks

| # | Risk | Impact | Mitigation / trigger |
|---|---|---|---|
| U1 | Single-letter creation keys (§15.3) collide with screen-reader pass-through and with users who expect typing anywhere to work | frustrating stray nodes | keys active only with canvas focus and outside `editText`, 50 ms guard, disabled in screen-reader mode, fully remappable; if support tickets show confusion, fall back to `Ctrl+Alt+letter` |
| U2 | `Ctrl+Shift+I` cannot be captured in Chrome (DevTools) | documented shortcut fails for many users | `Ctrl+Shift+B` fallback shipped from day one, both listed in the `?` sheet |
| U3 | The accessible DOM mirror capped at 300 nodes means large boards are not fully navigable by screen reader on the canvas | a11y gap | outline view (§19.4) and List view are complete alternatives and are the announced path; revisit if a cheaper mirror is found |
| U4 | Paste detection heuristics (§7.2) will misclassify some real clipboards (notably code vs prose, HTML with one anchor) | wrong node type | every path is one-click correctable, the paste chip appears when scores are within 0.15, and misclassification is logged locally to tune the corpus in `18_TESTING.md` |
| U5 | Auto-applying the paste-chip default after 4 s may surprise users who look away | unexpected nodes | default is always the reversible option, Undo chip persists 8 s, and the delay is user-configurable (2/4/never) |
| U6 | Touch drag-to-move on nodes competes with pan on one finger | accidental moves | node drag needs 8 px + 120 ms hold and gives haptic feedback; if telemetry shows accidental moves > 2% of touch drags, require long-press first |
| U7 | Presentation scenes stored in the Y.Doc can be edited by collaborators mid-presentation | jarring changes | camera is never moved by remote edits during playback; a "Board updated" chip signals it; consider a soft lock in P15 |
| U8 | Focus-mode dimming at 12% may fail `forced-colors` and high-contrast needs | content becomes invisible | under `prefers-contrast: more` dimming is 35%, under `forced-colors` focus mode hides instead of dims |
| U9 | Inspector depth (11 node types × 5 tabs) risks inconsistent implementations | UX drift | one `InspectorSection` primitive plus a per-type field schema in `06_NODE_SYSTEM.md`; a Playwright snapshot per type per state |
| U10 | Mobile being a different product doubles UX surface and can drift from desktop semantics | inconsistent mental model | mobile reuses domain + data layers unchanged and only composes existing actions; no mobile-only mutation exists |
| U11 | Conflict copy in §12.7 ("your change was replaced") could appear noisy in active collaboration | notification fatigue | coalesce per node per 30 s, suppress entirely for fields the user is not currently viewing, and never for position changes |
| U12 | Keyboard registry overrides 8 browser defaults; a future browser may make one non-preventable | shortcut silently dies | startup self-test attempts each override once in a hidden context and surfaces a settings warning with a suggested remap |
