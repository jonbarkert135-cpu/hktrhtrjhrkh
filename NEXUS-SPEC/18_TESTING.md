# NEXUS — 18 — TESTING STRATEGY

## Scope

Defines how NEXUS is tested at every level: unit, property, canvas-engine (headless), component,
e2e, visual, performance, accessibility, security and integration-adapter contract tests.
Specifies fixtures, factories, seeding, coverage targets, flaky-test policy and the per-phase test
checklist that the quality gate in `00_MASTER.md` §8.7 requires as evidence.
Binding for every phase prompt in `20_ROADMAP.md`. Contradictions with `00_MASTER.md` are bugs in
this file.

## 1. Test pyramid and ownership

| Level              | Tool                                             | Count target at GA        | Runtime budget (CI) | Owns                                                                                              |
| ------------------ | ------------------------------------------------ | ------------------------- | ------------------- | ------------------------------------------------------------------------------------------------- |
| L0 static          | `tsc --noEmit`, ESLint, dependency-cruiser       | n/a                       | ≤ 120 s             | types, layer boundaries, `no-direct-graph-write`                                                  |
| L1 unit            | Vitest (node env)                                | ~1800                     | ≤ 180 s sharded ×4  | pure functions in `packages/domain`, `packages/canvas-engine`, parsers in `packages/integrations` |
| L2 property        | Vitest + `fast-check`                            | ~40 properties            | ≤ 120 s             | export/import round-trip, CRDT convergence, routing invariants, spatial index invariants          |
| L3 headless canvas | Vitest + `node-canvas`-free fake ctx             | ~250                      | ≤ 90 s              | renderer command stream, interaction FSM, camera math, culling                                    |
| L4 component       | Vitest + `@testing-library/react` (jsdom)        | ~350                      | ≤ 150 s             | Radix-based primitives, panels, inspector, forms, state tables                                    |
| L5 e2e             | Playwright (chromium; firefox/webkit on nightly) | 60–80 specs               | ≤ 12 min sharded ×4 | critical journeys, offline, multi-tab collab, undo matrix                                         |
| L6 visual          | Playwright screenshots                           | ~120 snapshots            | ≤ 5 min             | design-system conformance, canvas rendering                                                       |
| L7 performance     | custom bench harness + k6                        | 9 benches, 4 k6 scenarios | ≤ 8 min             | N1 budget, API load                                                                               |
| L8 security        | Vitest corpora + ZAP baseline (nightly)          | ~200 cases                | ≤ 120 s             | SSRF, upload sniffing, authz matrix                                                               |

Rule of placement: **if it can be a unit test, it must not be an e2e test.** An e2e test exists
only to prove that independently-tested units are wired together across a real browser, a real
WebSocket and a real database. Any e2e test that asserts a pure computation is a review reject.

Inverse rule: **every N-requirement from `00_MASTER.md` §4 has at least one test at L5 or L7**,
because those are the requirements about the assembled system.

Traceability matrix (kept in `e2e/traceability.md`, generated by `pnpm test:trace`):

## 3. Unit testing conventions (Vitest)

### 3.1 Configuration

`packages/config/vitest/base.ts`:

```ts
import { defineConfig } from 'vitest/config';

export const base = defineConfig({
  test: {
    environment: 'node',
    globals: false, // explicit imports; no ambient magic
    restoreMocks: true,
    clearMocks: true,
    unstubEnvs: true,
    testTimeout: 5_000, // a unit test above 5 s is a design bug
    hookTimeout: 10_000,
    pool: 'threads',
    sequence: { shuffle: true, seed: Number(process.env.VITEST_SEED ?? 0) },
    coverage: { provider: 'v8', reporter: ['text-summary', 'json', 'lcov'] },
  },
});
```

`shuffle: true` is deliberate: order-dependent tests are the main source of "works locally" flake.
The seed is printed on failure so a run is reproducible with `VITEST_SEED=<n>`.

### 3.2 Rules

1. No network, no filesystem, no timers in L1. Network is banned by a global `beforeAll` that
   replaces `globalThis.fetch` with a throwing stub (`packages/config/vitest/no-network.ts`).
2. No snapshot testing of objects that a human cannot review (> 40 lines). Assert fields.
3. One behavior per test; the test name is a sentence: `rejects an edge whose source equals its target`.
4. Time is injected, never read from `Date.now()` inside domain code. `packages/domain/src/clock.ts`
   exports `Clock = { now(): number }`; tests pass `fixedClock(1_700_000_000_000)`.
5. Randomness is injected the same way (`Rng = () => number`), so ID generation is deterministic in
   tests (`seededRng(42)`).

### 3.3 Factories for graph data

`packages/domain/test/factories.ts` — the single source of test graph data. Never build node
literals inline in a test file; drift between test data and schema is the main cause of false
green.

```ts
import { z } from 'zod';
import type { Node, Edge, NodeType, EdgeType, BoardSnapshot } from '../src';

let seq = 0;
export const resetFactories = () => {
  seq = 0;
};
const id = (p: string) => `${p}_${(++seq).toString(36).padStart(6, '0')}`;

export interface NodeOverrides extends Partial<Node> {
  type?: NodeType;
}

export function makeNode(o: NodeOverrides = {}): Node {
  const type = o.type ?? 'note';
  return {
    id: o.id ?? id('n'),
    type,
    x: o.x ?? 0,
    y: o.y ?? 0,
    w: o.w ?? 260,
    h: o.h ?? 140,
    z: o.z ?? 0,
    data: o.data ?? defaultData(type),
    tags: o.tags ?? [],
    provenance: o.provenance ?? {
      source: 'manual',
      tool: null,
      runId: null,
      observedAt: '2026-01-01T00:00:00.000Z',
      confidence: 1,
    },
    createdAt: '2026-01-01T00:00:00.000Z',
    updatedAt: '2026-01-01T00:00:00.000Z',
    ...o,
  } as Node;
}

export function makeEdge(a: Node, b: Node, o: Partial<Edge> = {}): Edge {
  return {
    id: o.id ?? id('e'),
    source: a.id,
    target: b.id,
    type: o.type ?? ('related_to' as EdgeType),
    routing: o.routing ?? 'curved',
    label: o.label ?? null,
    waypoints: o.waypoints ?? [],
    provenance: o.provenance ?? {
      source: 'manual',
      tool: null,
      runId: null,
      observedAt: '2026-01-01T00:00:00.000Z',
      confidence: 1,
    },
    ...o,
  };
}

/** Deterministic board of N nodes / M edges laid out on a grid. Used by benches too. */
export function makeBoard(nodes = 100, edges = 150, seed = 1): BoardSnapshot {
  const rng = seededRng(seed);
  const ns = Array.from({ length: nodes }, (_, i) =>
    makeNode({
      x: (i % 80) * 320,
      y: Math.floor(i / 80) * 220,
      type: pick(rng, ['note', 'website', 'image', 'person', 'repo']),
    }),
  );
  const es = Array.from({ length: edges }, () =>
    makeEdge(ns[Math.floor(rng() * ns.length)], ns[Math.floor(rng() * ns.length)]),
  ).filter((e) => e.source !== e.target);
  return {
    schemaVersion: 1,
    boardId: 'b_test',
    nodes: ns,
    edges: es,
    groups: [],
    viewport: { x: 0, y: 0, zoom: 1 },
  };
}
```

`makeBoard` is the canonical generator: e2e seeding, benches and property tests all use it, so a
"5,000-node board" means the same thing everywhere.

### 3.4 Fixtures

Static fixtures live next to their consumer and are **committed**, never fetched at test time:

- `packages/integrations/test/fixtures/github/repo.facebook.react.json` (trimmed API response)
- `packages/integrations/test/fixtures/sherlock/found-12.json` (`sherlock --json` output shape)
- `packages/integrations/test/fixtures/spiderfoot/scan-events.csv`
- `packages/domain/test/fixtures/board-v1-golden.json` (export golden, 40 nodes, all node types)
- `packages/domain/test/fixtures/urls-hostile.txt` (SSRF corpus, §11.1)
- `packages/domain/test/fixtures/uploads/` (upload corpus, §11.2)

Fixture files carry a header comment (`_meta` key in JSON) with: source, capture date, capture
command, and the redaction applied. Fixtures with real personal data are forbidden; recorded
outputs are redacted to synthetic identifiers before commit (§12.2).

## 4. Property-based tests (`fast-check`)

Run with `numRuns: 200` locally/CI, `numRuns: 5000` nightly. Counterexamples are auto-persisted to
`test/.fast-check-failures/` and promoted to explicit regression unit tests by the fixing PR.

### 4.1 Export/import round-trip (N9)

```ts
import fc from 'fast-check';
import { exportBoard, importBoard } from '../src/export';
import { arbBoard } from './arbitraries';

test('export → import is lossless', () => {
  fc.assert(
    fc.property(arbBoard(), (board) => {
      const round = importBoard(exportBoard(board));
      expect(round).toStrictEqual(normalize(board)); // normalize = sort arrays by id
    }),
    { numRuns: 200 },
  );
});
```

`arbBoard()` generates every node type with every optional field present/absent, edges with all 4
routing modes and 0–6 waypoints, groups (including nested), unicode text (including RTL, emoji,
combining marks, 4-byte planes), and `provenance` from every source kind. It also generates the
adversarial cases: empty board, single node, 2,000 nodes, duplicate tags, edges referencing the
same node twice.

Additional export properties:

- **Idempotence**: `exportBoard(importBoard(x)) === x` for any valid serialized `x`.
- **Version tolerance**: importing a `schemaVersion: 1` document into a build whose current version
  is higher runs the migration chain and re-exports at the current version without data loss for
  fields that exist in both.
- **Unknown-field preservation**: unknown keys inside `data` survive a round-trip (forward
  compatibility with plugin node types, see `17_PLUGIN_SDK.md`).

### 4.2 CRDT convergence

```ts
test('two replicas converge under arbitrary interleavings', () => {
  fc.assert(
    fc.property(arbOpScript(), arbOpScript(), arbInterleave(), (a, b, order) => {
      const { docA, docB } = twoDocs();
      applyScript(docA, a);
      applyScript(docB, b);
      syncPairwise(docA, docB, order); // exchanges updates in the given order, possibly repeated
      expect(snapshot(docA)).toStrictEqual(snapshot(docB));
      expect(isValidBoard(snapshot(docA))).toBe(true); // no dangling edges after merge
    }),
    { numRuns: 200 },
  );
});
```

Invariants asserted after every convergence: (a) both replicas equal; (b) no edge references a
missing node — the domain layer's `pruneDanglingEdges` must be applied in the observer, and the
property proves it; (c) group membership contains no node deleted on either side; (d) applying the
updates in reverse order yields the same state (commutativity smoke).

Third property — **undo under concurrency (N3)**: after `docA` performs op, `docB` performs a
conflicting op, and `docA` undoes, `docA`'s undo must revert only its own origin's changes.

### 4.3 Routing invariants (`07_EDGE_SYSTEM.md` §4)

For any pair of node rectangles and any routing mode, the produced path must satisfy:

1. Endpoints lie on the source/target node border, within 0.5 px tolerance.
2. Path is finite: no `NaN`, no `Infinity`, ≤ 64 segments.
3. Orthogonal mode: every segment is axis-aligned (|dx| < 0.001 or |dy| < 0.001).
4. Smart mode: path does not intersect any obstacle rectangle inflated by the configured
   `obstaclePadding` (12 px), unless the router returned `degraded: true` after exceeding its
   budget — in which case it must fall back to `curved` and set the flag.
5. Determinism: identical inputs produce byte-identical path arrays (routing runs in a worker and
   must be cacheable).
6. Symmetry: routing A→B and B→A produce mirrored paths of equal length ± 0.5 px in straight and
   curved modes.

### 4.4 Spatial index invariants (`05_CANVAS_ENGINE.md` §5)

For random insert/move/delete scripts, `index.query(rect)` must return exactly the set that a
brute-force O(n) scan returns. This single property replaces dozens of hand-written index tests.

## 5. Canvas engine testing without a browser

`packages/canvas-engine` must not import React and must not require a real DOM (`00_MASTER.md` §2).
That makes it testable in plain Node, which is the reason the boundary exists.

### 5.1 Recording renderer

> **Implementation note (P2).** The shipped seam is `RenderTarget` → `DrawContext` in
> `packages/canvas-engine/src/types.ts` (`clear`, `save`/`restore`, `setCamera`, `rect`, `roundRect`,
> `line`, `dot`, `text`, `measureText`); `createRecordingTarget()` and `createManualClock()` are
> exported from `@nexus/canvas-engine/testing` together with the pointer-script runner. The
> `begin/drawGrid/drawEdge/mountDomNode` sketch below predates that interface. `makeBoard` takes an
> options object: `makeBoard({ nodes, edges, seed })`.

Instead of asserting pixels, we assert the **draw-command stream**. The engine takes a
`RenderTarget` interface; tests inject `createRecordingTarget()`:

```ts
export interface RenderTarget {
  begin(frame: FrameInfo): void;
  drawGrid(v: Viewport): void;
  drawEdge(path: Float32Array, style: EdgeStyle): void;
  drawNodeLod(node: LodNode): void;
  mountDomNode(id: string, rect: Rect): void;
  unmountDomNode(id: string): void;
  end(): void;
}

export function createRecordingTarget() {
  const cmds: Cmd[] = [];
  return { cmds, target: /* implementation pushing typed records */ } as const;
}
```

Assertions become semantic and stable:

```ts
test('nodes outside the viewport are not mounted as DOM', () => {
  const { engine, rec } = harness(makeBoard(500, 0));
  engine.setViewport({ x: 0, y: 0, zoom: 1, width: 1440, height: 900 });
  engine.tick();
  const mounted = rec.cmds.filter((c) => c.kind === 'mountDomNode').map((c) => c.id);
  expect(mounted.length).toBeLessThanOrEqual(60);
  for (const id of mounted) expect(intersects(rectOf(id), viewportRect)).toBe(true);
});

test('below zoom 0.55 nodes are painted as LOD glyphs, never mounted', () => {
  const { engine, rec } = harness(makeBoard(500, 0));
  engine.setViewport({ ...vp, zoom: 0.4 });
  engine.tick();
  expect(rec.cmds.some((c) => c.kind === 'mountDomNode')).toBe(false);
  expect(rec.cmds.filter((c) => c.kind === 'drawNodeLod').length).toBeGreaterThan(0);
});
```

### 5.2 Deterministic clock and frame loop

The engine never calls `requestAnimationFrame` directly; it receives a `Scheduler`:

```ts
export interface Scheduler {
  requestFrame(cb: (t: number) => void): number;
  cancel(h: number): void;
}
export function manualScheduler() {
  const q: Array<(t: number) => void> = [];
  let t = 0;
  return {
    scheduler: {
      requestFrame: (cb) => {
        q.push(cb);
        return q.length;
      },
      cancel: () => {},
    },
    advance(ms = 16.67) {
      t += ms;
      const batch = q.splice(0);
      batch.forEach((cb) => cb(t));
    },
  };
}
```

Tests then say `sched.advance(16.67)` N times. This makes animation, inertia, easing and debounce
behavior fully deterministic and removes every `await sleep()` from engine tests.

### 5.3 Synthetic pointer event scripts

Interaction is a finite state machine (`05_CANVAS_ENGINE.md` §7). Tests drive it with a compact DSL
that compiles to the engine's `PointerEvent`-shaped input records:

```ts
const script = pointer()
  .down(100, 100, { button: 0 })
  .move(140, 130) // crosses the 4 px drag threshold
  .move(400, 300)
  .up();

play(engine, script, sched);
expect(engine.state.mode).toBe('idle');
expect(nodeAt(engine, 'n_1').x).toBe(300);
```

Required FSM coverage (one test each): click-select, shift-click multi-select, marquee, drag-node,
drag-canvas (space or middle button), drag-edge-from-port, resize handle, double-click-to-edit,
right-click context, wheel-zoom at cursor, pinch-zoom, escape-cancels-drag,
pointer-cancel-mid-drag, drag-with-snapping, drag-out-of-window-and-back.

Every transition must also be asserted to be **cancel-safe**: injecting `pointercancel` at any step
returns the FSM to `idle` and leaves the document unmodified (verified by comparing a Y.Doc state
vector before and after).

### 5.4 Scene snapshot assertions

`sceneSnapshot(engine)` returns a normalized, human-reviewable text form:

```text
viewport 0,0 @1.00 1440x900
dom  n_000001 note      x=0    y=0    w=260 h=140 sel=1
dom  n_000002 website   x=320  y=0    w=260 h=180
lod  n_000141 image     x=4480 y=880
edge e_000001 n_000001->n_000002 curved seg=3
```

Used with Vitest inline snapshots for the ~15 "shape of the scene" tests (initial render, after
select-all, after auto-layout, after collapse group…). Text snapshots are reviewable in a diff;
pixel snapshots at this level would be flaky and are handled by L6 instead.

## 6. Component tests

Environment: jsdom + `@testing-library/react` + `@testing-library/user-event`. Canvas is **not**
rendered in component tests; the engine is mocked at the `useCanvasEngine()` hook boundary.

Every interactive component ships a **state table test**. The table is the same one the design
system requires (`04_DESIGN_SYSTEM.md`), and the test enumerates it:

```ts
describe.each([
  ['initial', {}, { 'data-state': 'idle' }],
  ['hover', { hover: true }, { 'data-state': 'hover' }],
  ['focus', { focus: true }, { 'data-focus-visible': 'true' }],
  ['selected', { selected: true }, { 'aria-selected': 'true' }],
  ['loading', { loading: true }, { 'aria-busy': 'true' }],
  ['error', { error: 'Timed out' }, { role: 'alert' }],
  ['disabled', { disabled: true }, { 'aria-disabled': 'true' }],
])('NodeCard %s', (_name, props, expected) => {
  /* render + assert attributes */
});
```

Additional mandatory component assertions:

- No component renders a raw hex color: `expect(getComputedStyle(el).color).toMatch(/var\(--/)` is
  not possible in jsdom, so this is enforced statically by the `no-hardcoded-design-values` ESLint
  rule with a unit test for the rule itself.
- Every dialog traps focus and restores it to the trigger on close.
- Every list supports `ArrowUp/ArrowDown/Home/End` and announces its size via `aria-setsize`.
- Empty state, loading skeleton and error state exist for every panel (`00_MASTER.md` §8.2).

## 7. End-to-end strategy (Playwright)

`playwright-core` entry so `@axe-core/playwright` does not resolve a second copy) because the `e2e`

### 7.2 Auth fixture

`e2e/global.setup.ts` creates deterministic users through the API (not the UI — logging in via the
UI in every spec is the classic e2e time sink) and writes storage states:

```ts
setup('authenticate', async ({ request }) => {
  for (const u of [SEED.owner, SEED.analyst, SEED.viewer]) {
    const res = await request.post('/api/test/login', {
      data: { email: u.email, token: process.env.E2E_TEST_TOKEN },
    });
    expect(res.ok()).toBeTruthy();
    await request.storageState({ path: `e2e/.auth/${u.role}.json` });
  }
});
```

`/api/test/login` exists only when `NEXUS_TEST_ENDPOINTS=1`, which is impossible in production
(the API refuses to boot if `NODE_ENV=production` and the flag is set — asserted by
`apps/api/test/test-endpoints-guard.test.ts`).

Per-spec isolation: a `board` fixture creates a fresh board seeded from `makeBoard(...)` via
`POST /api/test/seed-board`, and deletes it in teardown. Specs never share a board; parallel
workers therefore never collide.

```ts
export const test = base.extend<{ board: SeededBoard }>({
  board: async ({ request }, use, testInfo) => {
    const b = await seedBoard(request, { name: testInfo.title, spec: 'default-40' });
    await use(b);
    await deleteBoard(request, b.id);
  },
});
```

### 7.4 Network stubbing of external tools

Rule: **no e2e test in the PR pipeline touches the public internet.** Three layers of stubbing:

1. **Browser-level** `page.route()` for anything the SPA fetches directly (none by default; the SPA
   talks only to our API).
2. **API-level stub mode**: with `NEXUS_INTEGRATIONS_MODE=stub`, the API's run service resolves
   runs from `packages/integrations/test/fixtures/**` instead of enqueueing a runner job. The
   fixture is chosen by `manifestId + inputHash`; an unmapped input fails loudly
   (`STUB_FIXTURE_MISSING`) rather than silently returning empty — silent empties produce
   false-green e2e.
3. **Egress kill switch**: the e2e docker network has no default route; a `blackhole` proxy returns
   `ECONNREFUSED`. Any accidental real call fails fast instead of hanging for 30 s.

Unfurl (`P6`) is stubbed by a local fixture web server `e2e/fixtures-server/` serving pages with
known titles, OG tags, redirects, slow responses (for timeout tests), 404s, oversized bodies and a
page that redirects to `127.0.0.1` (SSRF e2e).

## 12. Integration adapter contract tests

### 12.1 Structure

Every adapter in `packages/integrations/<tool>/` ships:

```text
manifest.ts        the declarative manifest (validated by the manifest zod schema)
parse.ts           raw output → ToolEvents
map.ts             ToolEvents → { nodes, edges } proposal payload
index.ts
```

Contract test `packages/integrations/test/contracts/<tool>.contract.test.ts` asserts, for each
recorded fixture:

1. `manifestSchema.parse(manifest)` succeeds and the manifest's declared `outputs` match what
   `map.ts` can produce (no undeclared node/edge types).
2. `parse(fixture.raw)` produces events that satisfy `toolEventSchema` — including the failure
   fixtures (non-zero exit, empty output, malformed JSON, partial JSON from a killed process).
3. `map(events)` produces a proposal where **every node carries full provenance**
   (`source`, `tool`, `runId`, `observedAt`, `confidence`) — this is N-property #1 of the product.
4. Mapping is **pure and deterministic**: called twice on the same events it deep-equals, and it
   generates stable IDs (content-hash based) so re-running a tool produces a _merge_, not duplicates.
5. Idempotence at import: applying the same proposal twice to a board yields the same graph
   (dedupe by stable ID) and the second application reports `0 created, N unchanged`.
6. Timeout / partial output: a truncated fixture yields a proposal marked `partial: true` with the
   parsed subset, never a throw.
7. Adapter never performs I/O in `parse`/`map` (asserted by the no-network global stub).

Concrete fixture expectations per verified tool:

- **Sherlock** (`v0.16.0`, MIT, `--json FILE` output): fixtures `found-12.json`, `found-0.json`,
  `mixed-with-errors.json`, `truncated.json`. Mapping produces one `person` node and N `account`
  nodes joined by `has_account` edges; `confidence` derives from the tool's claimed/possible status.
  Adapter assumption to validate at runtime: the exact JSON key layout of `--json` output is read
  defensively (`parse` accepts both an object-of-sites and an array-of-results shape); if neither
  shape matches, the run fails with `ADAPTER_SHAPE_MISMATCH` and the raw payload is attached to the
  run record for inspection. A contract test covers both shapes and the mismatch path.
- **SpiderFoot** (`v4.0`, MIT, low maintenance activity per deps.dev June 2026): fixtures
  `scan-events.csv`, `scan-events-empty.csv`, `scan-error.json`, `api-unauthorized.json`. Because
  upstream activity is low, the adapter is pinned by **image digest** and the contract test asserts
  the digest recorded in the manifest is the one the fixtures were captured from. A `degraded`
  fallback path (import the CSV export produced manually by the user) has its own fixture and test,
  so SpiderFoot going stale never blocks the product.
- **GitHub**: fixtures for repo metadata, README (markdown with HTML and images), releases,
  contributors, rate-limit 403, 404 private repo, and an empty repo. Rate-limit fixture must map to
  a user-readable error with retry-after, not a crash.

### 12.2 Refreshing fixtures safely

`pnpm fixtures:record --tool=<id> --case=<name>` runs the real tool in the runner against a
**consented target set** (`packages/integrations/test/targets.md`: our own GitHub org, a username
we own, a domain we own) and writes the raw output through a redaction pipeline:

1. Replace any value matching the secret patterns (`ghp_`, `sk-`, JWT-shaped, Basic auth) with
   `<REDACTED>`; the recorder aborts if a secret pattern is found in a field it cannot redact.
2. Replace real emails/IPs/usernames not in the consented list with deterministic synthetic values
   from a seeded mapping file kept out of git (`.fixture-map.json`), so cross-fixture references
   stay consistent without exposing the mapping.
3. Truncate arrays longer than 50 entries, preserving the first 20 and last 5, and record
   `_meta.truncated: true`.
4. Write `_meta`: tool version, image digest, capture date, command line, operator.

Refreshing is a **separate PR labeled `fixtures`**, never bundled with behavior changes, so a diff
in behavior is never hidden inside a diff in recorded data. A nightly `contract-drift` job runs the
real tools against the consented targets and _diffs the shape only_ (JSON key paths, not values);
a shape change opens an issue automatically. This is how upstream drift is detected without making
the PR pipeline depend on third-party availability.

## 13. Flaky-test policy

1. **One retry maximum** in CI. Retries hide bugs; the retry exists only to keep the queue moving.
2. Any test that passes on retry is recorded by the reporter into `flaky-report.json` and posted to
   the `#nexus-ci` channel with its trace.
3. A test that flakes **twice within 14 days** is auto-quarantined by a bot: moved to the
   `@flaky` tag (excluded from the required check), and an issue is opened with the traces,
   assigned to the owning code area, with a **7-day** fix SLA.
4. Quarantine capacity is capped at **1 % of the suite** (≈ 1 e2e spec). Exceeding the cap blocks
   all merges except flake fixes. This prevents quarantine from becoming a graveyard.
5. `test.skip` without a linked issue ID in the reason string fails lint
   (`scripts/check-skips.mjs`).
6. Banned constructs that cause flake, enforced by ESLint: `waitForTimeout`, bare `sleep`,
   `page.waitForSelector` with `state:'attached'` used as a proxy for readiness, assertions on
   `Date.now()`, tests that depend on suite order or on a shared board.
7. Root-cause categories are tracked: (a) missing await, (b) shared state, (c) time dependence,
   (d) animation, (e) network stub gap, (f) real product race. Category (f) always converts into a
   product bug, never just a test fix.

## Open risks

1. **Canvas visual snapshots across CI runners.** Software rasterization differences can push curve
   antialiasing past the 0.005 ratio. Mitigation: pinned Playwright image and a single runner
   family for the `visual` project; if instability persists, replace canvas pixel snapshots with
   the deterministic scene-snapshot text form (§5.4) and keep pixel snapshots for DOM surfaces only.
2. **Perf gate noise on shared runners.** The 5 % gate is tight for cloud runners. Mitigation:
   median-of-3 p95, `perf-inconclusive` soft-fail path, and moving to a self-hosted runner if the
   inconclusive rate exceeds 10 % of runs.
3. **SpiderFoot fixture staleness.** With low upstream activity, recorded fixtures may diverge from
   the pinned image if the user upgrades it. Mitigation: manifest digest assertion + nightly
   contract-drift shape diff + documented degraded CSV-import path.
4. **Sherlock JSON shape assumption.** The `--json` layout is read defensively; if upstream changes
   it, the adapter fails with `ADAPTER_SHAPE_MISMATCH` rather than importing wrong data. Validate
   at first integration; keep both parsers until observed in production.
5. **CRDT property tests are probabilistic.** 200 runs will not find rare interleavings. Mitigation:
   nightly 5,000-run job and mandatory promotion of any counterexample to a permanent unit test.
6. **e2e wall-clock growth.** At 80 specs the suite approaches the 12-minute budget. Mitigation:
   shard by 4, move any spec that does not cross a process boundary down the pyramid, and enforce a
   per-spec 45 s timeout so a slow spec is a review conversation.
7. **Test endpoints as an attack surface.** `/api/test/*` is guarded by env + a boot-time assertion;
   a misconfigured self-host deployment could still enable it. Mitigation: the guard test, a startup
   log warning, and a production readiness checklist item (`19_DEPLOYMENT.md` §14).
